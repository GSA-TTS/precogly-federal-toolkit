# Public CCC Inheritance Starters

`public-ccc-{low,moderate,high}-starter.yaml` are review inputs for starting a
system-specific inheritance analysis. They are generated by:

```bash
make public-inheritance-profiles
make public-inheritance-profiles-check
make public-inheritance-coverage
make public-inheritance-coverage-check
```

Each profile intersects the pinned FedRAMP Low, Moderate, or High membership set
with the approved CCC Rev. 7 designation baseline. It contains only control
identity, title, Federal/Contractor designation, and inheritance-source label.
`source_fedramp_baselines`, `oscal_vault_commit`, and
`fedramp_baselines_sha256` bind each generated profile to immutable baseline
source bytes in the parent-pinned `vendor/oscal-vault` commit. Regeneration and
review are required when that source changes. `ccc_revision` and `ccc_sha256`
provide the equivalent binding for the approved CCC designation source.

`docs/analyses/public-ccc-inheritance-coverage.md` is the generated reviewer
receipt for these profiles. It makes the CCC-designated intersection and the
remaining controls requiring system-specific disposition visible without adding
system implementation content.

These profiles are not SSPs, authorization assertions, or proof that a control
is inherited by a particular system. `baseline_controls_without_ccc_designation`
is deliberately retained so reviewers can measure the controls that still need
system-specific disposition rather than treating the CCC intersection as full
baseline coverage.

The profiles exclude narrative, organization-defined parameters, implementation
statements, architecture, personnel identities, and evidence. See
`docs/adrs/ADR-SSPP-028-public-release-boundary.md` for the public-release
boundary.
