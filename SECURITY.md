# Security Policy

## Supported versions

Security fixes are applied to the current `main` branch. This project does not
maintain older release branches unless a release announcement explicitly says
otherwise.

## Reporting a vulnerability

File a **Security concern** issue using the repository's GitHub issue template,
or use GitHub Private Vulnerability Reporting if enabled on the repository.
Record only the information maintainers need to triage the report and request a
private follow-up channel.

Do not include any of the following in a public issue:

- Customer SSP source documents, authorization-boundary artifacts, or CUI.
- Credentials, tokens, account identifiers, or internal/non-public URLs.
- Exploit payloads or operational details that could increase impact.

Include the affected toolkit commit or version, a high-level impact description,
and safe reproduction or mitigation steps. Maintainers will acknowledge the
report, establish an approved private transfer method before requesting
sensitive artifacts, coordinate remediation, and disclose publicly only after a
fix or mitigation is available.
